## 详细报告 1 · D11（P1，已复现）

**标题**：`open()` 未指定编码，含中文的 JSON 在中文 Windows 上解码失败，两个接口必然 500

**环境**：Windows 11 中文版 / Python 3.13.9 / Flask 3.1.2，未设置 `PYTHONUTF8=1`

**前置条件**：`data/public_copyright_by_category.json` 存在且 key 为中文（`男` / `女` / `点景人物` / `有男有女`）

**复现步骤**：
1. `python sut/app.py` 启动服务
2. `curl http://127.0.0.1:8000/api/images_count`
3. 观察响应：HTTP 500

**期望结果**：HTTP 200 + `{total, category_count, copyright_count}`

**实际结果**：
```
File "app.py", line 664, in get_images_count
    copyright_data = json.load(f)
UnicodeDecodeError: 'gbk' codec can't decode byte 0xb7 in position 7: illegal multibyte sequence
```

**根因**：`app.py` 第 658 行 `open(copyright_file, 'r')` 未指定 `encoding`，Python 使用 `locale.getpreferredencoding()`，在中文 Windows 上是 `cp936`；而文件为 UTF-8 编码，且 key 含中文 → 解码失败。同源问题见第 543 行（`/api/mingqing_ids`）与第 554 行（`/api/public_copyright_ids`）。

**影响**：本项目主力开发/标注环境是中文 Windows，2 个接口在 Windows 上 100% 不可用；Linux 上因默认 UTF-8 而"碰巧正常"，属于典型的**平台差异型缺陷**，极易在交付后才暴露。

**修复建议**：
```python
with open(copyright_file, 'r', encoding='utf-8') as f:   # 显式编码
```
并在 CI 中增加一个 `PYTHONUTF8=0` + 中文 locale 的矩阵任务，长期守护。

**回归用例**：`tests/test_defects.py::test_images_count_should_not_depend_on_platform_encoding`、`::test_public_copyright_ids_should_not_depend_on_encoding`

## 详细报告 2 · D05（P2，已复现）

**标题**：查询不存在的图片时，`/api/image/<uuid>` 返回 200 与全 null 数据，前端无法区分"不存在"和"无数据"

**复现步骤**：
1. 启动服务
2. `curl -i http://127.0.0.1:8000/api/image/deadbeef-0000-4000-8000-000000000000`

**期望**：HTTP 404 + `{"error": "未找到"}`

**实际**：HTTP 200 + `{"uuid": "...", "pose": null, "detection": null, "cit": null, "dino": null}`

**根因**：`app.py` 第 713-763 行只做"命中则填充、未命中则保持 None"，没有不存在分支。对比同项目 `/api/human_annotation/<uuid>`（第 421 行）有正确的 `if uuid not in ...: return 404` —— **同一项目内两份接口契约不一致**。

**影响**：前端据 `200` 判定成功，会对空数据做渲染分支；监控/统计无法区分"正常空结果"与"非法请求"，掩盖上游数据缺失。

**修复建议**：无任何数据源命中时返回 404；同时统一错误响应体格式（见 D09）。

**回归用例**：`tests/test_defects.py::test_image_detail_missing_should_404`

## 详细报告 3 · D17（P2，E2E 发现）

**标题**：图片查看页调用未定义的函数，每次加载都抛 `ReferenceError`

**复现**：浏览器打开 `/images`，控制台报 `Uncaught ReferenceError: loadFilterOptions is not defined`

**定位**：`templates/images.html` 第 1401 行

```js
document.addEventListener('DOMContentLoaded', function() {
    const firstTitle = document.querySelector('.filter-title');
    if (firstTitle) { firstTitle.click(); }
    loadFilterOptions();          // ← 全文件唯一一次出现，函数从未定义
});
```

`grep loadFilterOptions` 在整个模板里只有这一行调用，没有任何定义。

**影响**：DOMContentLoaded 处理器在此处中断。当前恰好是最后一条语句，所以只表现为一个报错；
但只要后续再往这个 handler 里加初始化逻辑（很可能会），就会全部被静默跳过。属于**埋雷型缺陷**。

**修复建议**：删除该调用，或补上真正的实现（筛选选项应来自 `/api/filter_options`）。

**回归用例**：`tests/test_e2e_pages.py::test_images_page_has_no_js_errors`

## 详细报告 4 · D18（P2，E2E 发现，含调用方影响分析）

**标题**：前端批量 `fetch().then(r => r.json())` 未校验响应类型，单个接口 500 会导致整批失败

**定位**：`templates/images.html` 第 637-644 行

```js
fetch('api/images?page=1&per_page=20000').then(res => res.json()),
fetch('api/images_count').then(res => res.json()),
fetch('api/public_copyright_ids').then(res => res.json()),
...
```

**现象**：当 `/api/images_count` 返回 500 的 HTML 错误页（D11 在中文 Windows 上的表现）时，
`res.json()` 抛出 `SyntaxError: Unexpected token '<'`，`Promise.all` 整体 reject，
7 个筛选计数永久停留在 `(0)`，用户看不到任何错误提示。

**为什么单列一条**：接口 500 是 D11 的问题，但**接口出错时前端完全降级失效且无提示**是独立的设计缺陷。
正确做法是 `if (!res.ok) throw` + `Promise.allSettled` + 局部降级（哪个计数取不到就显示 `-`）。

**顺带发现（重要）**：第 637 行用 `api/images?page=1&per_page=20000` 一次性拉全量，
**说明前端已经依赖了 D07 的"per_page 无上限"行为**。这意味着：
如果只按 D07 的建议给接口加上限（比如 500），页面会静默地只显示 500 张图，而不会报错。
**修 D07 必须同时把前端改成分页加载**——这是"缺陷修复要看调用方"的典型例子，也是接口测试和 E2E
必须一起做的原因。

**回归用例**：`tests/test_e2e_pages.py::test_images_page_has_no_js_errors`、`::test_images_filter_counts_not_all_zero`

## 静态审计发现（节选说明）

- **D03 参数注入**：第 788-799 行 `cloud_url = CLOUD_IMAGE_URL + filename`，`filename` 来自 `<path:filename>`，未经任何白名单/转义。构造 `/images/x%3Fbucket%3D其他bucket` 即可改变云端查询串，越权读取其他 bucket 对象。
- **D10 裸 except**：第 52、283、297、776、793、797、975 行等 `except: pass`，会连同 `KeyboardInterrupt`/`SystemExit` 一起吞掉；一旦云端异常，接口静默返回空，线上无任何日志线索。
- **D14 长尾**：第 342-418 行 `build_scroll_image` 在请求线程内串行请求 `nx×ny` 个瓦片（每片 timeout 15s），单请求最坏耗时可达分钟级，且并发下每请求各占一份内存画布。
- **D15 无鉴权**：全部接口无任何认证。`/api/download` 可一次导出全量图片与标注；若该服务经 Cloudflare Tunnel 暴露到公网（本项目确实这么做），等同于数据公开。建议至少加 Basic Auth + 内网 IP 白名单，并对下载接口限流。

## 详细报告 5 · D19（P2，云端 500 被伪装成 404）

**发现方式**：补云端依赖 mock 覆盖时，用本地假云端（`tools/fake_cloud.py`）让 `GET /server/getobjects` 返回 500。

**现象**：`GET /api/thumb/<uuid>` 返回 `404` + **空 body**，而不是 5xx 或带错误信息的响应。

**根因**（`app.py` 约 771-784 行）：

```python
try:
    resp = requests.get(cloud_url, timeout=10, verify=False)
    if resp.status_code == 200:
        return Response(resp.content, ...)
except:          # ← 裸 except 吞掉一切（D10 同源问题）
    pass
return '', 404   # ← 云端故障与"图片不存在"得到同一个响应
```

**影响**：前端/调用方无法区分「这张图真不存在」（可缓存、可跳过）与「云端挂了」（应重试/告警），监控也无法据此报警。

**修复建议**：捕获具体异常（`Timeout`/`ConnectionError`），云端 5xx → 返回 `502/503` + `{"error": "cloud_unavailable"}`；仅云端 404 才返回 404。

**回归用例**：`tests/test_cloud_mock.py::test_thumb_cloud_500_should_not_mask_error`（xfail，修复后转 XPASS）。

## 详细报告 6 · D20（P3，cloud_url 解析失败返回 200 + 空字符串）

**现象**：`GET /api/cloud_url/<uuid>` 在云端解析失败（`get_image_path` 返回 None）时，仍返回 `200 {"url": ""}`。

**影响**：调用方拿到 200 会当成"成功但没图"，无法触发错误处理；日志里也不会有失败信号。

**修复建议**：解析失败返回 `502` 或 `404 + {"error": ...}`；成功与失败必须能被状态码区分。

**回归用例**：`tests/test_cloud_mock.py::test_cloud_url_when_resolve_fails_should_signal_error`（xfail）。

> 测试设计备注：该用例必须使用**未被其他用例解析过**的 uuid——SUT 内部有 `image_path_cache`，命中缓存会掩盖云端故障。这就是「用例间状态污染」，是 flaky 的典型来源。

## 详细报告 7 · D21（P2，/api/scroll 把云端故障伪装成 404）

**发现方式**：本地假云端让 `getworkinfobyimageid` 返回 500，请求 `/api/scroll/<uuid>`。

**现象**：返回 `404` + 空 body。

**根因**：`detect_truncation()` 在云端失败时返回 `(False, None)` → 不走拼接 → 回退 `get_thumbnail()` →
`get_image_path()` 仍拿不到路径 → 最终 `return '', 404`。三层降级把"云端故障"和"资源不存在"折叠成同一个响应。

**影响**：与 D19 同源——调用方无法区分故障类型，监控无法报警；长卷是可视化站点的核心功能，静默失败代价更高。

**修复建议**：每层降级都要保留失败原因（如 `{"error": "cloud_unavailable"}` + 502），只在"确实不存在"时返回 404。

## 详细报告 8 · D22（P2，瓦片缺失仍返回半张图）

**发现方式**：本地假云端在长卷瓦片网格中故意缺一块（`(x=1,y=0)`），请求 `/api/scroll/<uuid>`。

**现象**：返回 `200 + image/jpeg`，但图右侧一块是白色底板——**部分成功被当成成功**。

**根因**（`build_scroll_image`）：

```python
for x in range(nx):
    for y in range(ny):
        try:
            r = requests.get(f'{tile_base}/{z}/{x}/{y}.png', timeout=15, verify=False)
            if r.status_code == 200:
                canvas.paste(tile, (x * 512, y * 512))
        except Exception:
            continue        # ← 单块失败被吞掉，继续拼，最后照常返回 200
```

**影响**：长卷是可视化站点的核心功能；缺一块瓦片意味着画面内容缺失，但调用方/用户完全无感知（不是报错，而是"看起来成功"）。这类静默数据缺失比崩溃更难发现。

**修复建议**：统计失败块数，`失败块 > 0` 时返回 502 + `{"error": "tiles_incomplete", "missing": n}`，或至少在响应头带 `X-Tiles-Missing: n`；同时记录日志用于告警。

**回归用例**：`tests/test_cloud_mock.py::test_scroll_partial_tiles_should_not_return_partial_image`（xfail）。

## 详细报告 9 · D23（P2，分类维度混入数据来源 + 多标签被压平）

**发现方式**：核对 `filter_options` 的分类来源与 CSV 权威数据时发现。

**现象 1（伪分类）**：分类选项里出现 `CIT检测`，它不是业务分类，而是"这条记录只有 CIT 数据、没有 detection 数据"的标记。

```python
# app.py:823  filter_options
for item in cit_data:
    if item.get('uuid') not in detection_dict:
        categories.add('CIT检测')     # 把数据来源当成分类值
# 同类赋值：app.py:702 / 858 / 911（三个接口都把 CIT-only 记录标成 category='CIT检测'）
```

**现象 2（多标签被压平）**：CSV 权威数据里，uuid `1111…` 同时出现在两个分类文件中：

```
画作信息_女.csv       → 11111111-…,宋代,女,test_female
画作信息_有男有女.csv  → 11111111-…,宋代,有男有女,test_mixed
```

但接口的筛选是单值精确匹配：

```python
# app.py:875
if category:
    results = [item for item in results if item.get('category') == category]
```

**影响**：
1. 用户筛「有男有女」永远看不到这张图（该图 detection 里的 category 是「女」）→ **静默漏数据**
2. 用户无法理解「CIT检测」是什么分类
3. `category` 的取值域不稳定（随数据来源变化），前端下拉框会冒出语义不明选项

**正确做法**：
- `category` 只来自业务权威来源（CSV 的 category 列），CIT-only 记录用单独字段标记 `source='cit'`，category 留空/「未分类」
- 分类支持多值：`if category in item['categories']`，而不是单值相等

**为什么没写成用例**：需要在 seed 里构造「一张图同属两类」的数据，属数据构造问题；先作为静态缺陷记录，待补 fixture 后转成用例。
